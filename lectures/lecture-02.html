Lecture 2: Tiered Web Architecture

One-tier, two-tier and three-tier web systems

Summary

This lecture explains how a web system can be split into tiers. A tier is where parts of a system run, and a layer is how the code is organized. You will compare one-tier, two-tier and three-tier designs and learn how to choose between them.

Topics Covered

  • Tiers and layers
    • A tier is a physical or deployment separation
    • A layer is a logical separation of responsibilities
  • One-tier architecture
    • Interface, logic and data in one environment
    • Example: a desktop calculator
  • Two-tier architecture
    • The client talks directly to the server and database
    • Simple, but harder to scale
  • Three-tier (N-tier) architecture
    • Presentation tier: browser and user interface
    • Application tier: business logic and API
    • Data tier: database and storage
  • Choosing an architecture
    • Scalability, maintainability and cost
Comparison of Architectures
Aspect One-tier Two-tier Three-tier
Where it runs One environment Client and server Separate components
Separation of work Low Moderate High
Small, simple systems Often suitable Often suitable May add complexity
Large web systems Poor fit Harder to scale Easier to scale

Example

A university learning portal is a good three-tier example. Students, teachers and admins use the browser, the application handles login, courses and marks, and the database stores the data.

Browser  --request-->  Application / API  --query-->  Database
Browser  <--response--  Application / API  <--data---  Database
