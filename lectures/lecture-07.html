Positioning, Stacking and Floats

How the browser lays elements out by default, and how to move them with positioning, z-index and floats.

Lecture content

Normal flow and static positioning

By default elements follow normal flow: block elements stack vertically in source order and inline elements run along the line. position: static is the default, and offsets such as top have no effect on it.

The four positioning modes

relative

Offset from its normal place. Its original space is kept.

absolute

Removed from the flow and placed against the nearest positioned ancestor.

fixed

Placed against the viewport and stays in place when you scroll.

sticky

Scrolls normally, then sticks once it reaches a set offset.

Use top, right, bottom and left for offsets, or inset as a shorthand. The containing block for an absolute element is its nearest positioned ancestor, so put position: relative on the parent.

z-index and stacking contexts

z-index sets which positioned element appears in front: higher values are closer to the viewer. A stacking context is a self-contained group of layers. It can be created by positioned elements with a z-index, and by properties such as opacity below 1 or transform. A child cannot escape its parent's stacking context, so a huge z-index inside a low parent can still end up behind another element.

To debug: find the parent stacking contexts, compare z-index values only within the same context, and check the source order.

Floats

float: left or float: right moves an element sideways so text wraps around it. Use clear: left, right or both to stop wrapping. A parent containing only floats collapses to zero height, which the clearfix fixes:

.clearfix::after {
  content: "";
  display: block;
  clear: both;
}

Common pitfalls

Missing margins

Floated items touch unless you add space.

Widths plus margins

If they exceed the container, items wrap to the next line.

Fixed heights

Content can overflow a box that has a set height.

Overflow as a quick fix

It hides content or adds scrollbars you did not mean to add.

Mixing old and new layouts

Floats and modern layouts like flexbox clash.

For modern page layouts, flexbox is usually the better choice than floats.

Worked example

A badge placed in the top-right corner of a card.

.card {
  position: relative;
}
.badge {
  position: absolute;
  top: 8px;
  right: 8px;
  z-index: 2;
}

Challenge: choose the position

A navigation bar must stay at the top of the screen while the page scrolls. Which position value fits, and what is a gentler alternative?

Show hint

Think about the viewport.

Show answer

fixed keeps it in the viewport. sticky is gentler: it scrolls normally until it reaches the top, then sticks.

Challenge: z-index puzzle

An element has z-index 9999 but still appears behind another element. What could be the cause?

Show hint

Look at the parents.

Show answer

Its parent creates a stacking context with a lower order, so the child cannot rise above elements outside that context.

Quick check

Answer in your head first, then open the answer.

1. What does position: relative on a parent do for an absolute child?

It makes the parent the containing block, so the child is positioned against it.

2. How is sticky different from fixed?

Sticky scrolls normally until it reaches an offset, then sticks. Fixed is always placed against the viewport.

3. Why use a clearfix?

A parent that contains only floats collapses, and the clearfix gives it back its height.

Tips and common mistakes

Common mistake

Using fixed for everything. Fixed elements leave the flow and can cover content or break on small screens.

Pro tip

Whenever you use position: absolute, add position: relative to the parent first.
