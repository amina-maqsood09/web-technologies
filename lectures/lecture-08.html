Polish your pages with rounded corners, gradients, transforms and animation, then make them flexible with web fonts, custom properties and media queries.

Lecture content

Rounded corners, gradients, shadows and opacity

border-radius rounds corners, and 50% on a square makes a circle. linear-gradient(90deg, colour1, colour2) blends colours and can use several. A gradient overlay can darken an image. opacity fades the whole element, text included, while rgba() makes only a colour transparent.

Too much shadow

Heavy shadows look cluttered.

Low opacity

Faded text is hard to read.

Gradient behind text

Check that the text stays readable.

Transforms

  • translate() move
  • rotate() turn
  • scale() grow or shrink
  • skew() slant

3D transforms add depth with perspective and transform-style: preserve-3d. A transform does not reflow the layout around it.

Transitions and keyframe animations

A transition animates a change between two states: transition: property duration timing-function delay. For multi-step motion, define @keyframes and use animation-name, animation-duration, animation-delay, animation-iteration-count, animation-direction and animation-fill-mode. Animate only what you need, and respect users who prefer reduced motion with @media (prefers-reduced-motion: reduce).

Web fonts, icon fonts and custom properties

@font-face loads a font file so you are not limited to fonts on the user's computer, and WOFF is a practical format. Icon fonts show icons as text. A custom property is a CSS variable: define it with --name (usually in :root), use it with var(--name, fallback), and it can also be local and inherited.

Media queries, feature queries and compatibility

@media applies styles only under certain conditions, such as screen width or orientation, so a page adapts to phones, tablets and desktops. @supports checks whether the browser supports a feature before you use it. Vendor prefixes such as -webkit- were used for early features, so test across browsers with a compatibility checklist.

Worked example

A button using a custom property, a smooth hover transition, and a mobile rule.

:root { --brand: #3b6bff; }
.btn {
  background: var(--brand);
  transition: transform 0.2s ease;
}
.btn:hover { transform: translateY(-2px); }
@media (max-width: 600px) {
  .btn { width: 100%; }
}

Challenge: smooth hover

Make a card grow slightly on hover, smoothly.

Show hint

Combine transition with transform: scale().

Show answer 
.card { transition: transform 0.3s ease; }

Challenge: faint text

Why does opacity: 0.5 on a button also make its text faint, and what could you use instead?

Show hint

Opacity applies to the whole element.

Show answer

Opacity fades the entire element, including its text. Use rgba() on the background colour to fade only the background.

Quick check

Answer in your head first, then open the answer.

1. What is the difference between opacity and rgba()?

Opacity affects the whole element. rgba() affects only that colour.

2. When do you use keyframes instead of a transition?

When you need multi-step motion, since a transition only goes between two states.

3. What is @supports for?

It checks whether the browser supports a feature before you use it.

Tips and common mistakes

Common mistake

Animating too many properties at once, which can feel slow and distracting.

Pro tip

Store colours and spacing in custom properties on :root. Changing one value then updates the whole site.
