Semantic HTML and Forms

How to give a page meaning with block, inline and semantic elements, and how to collect and validate user input with forms.

What you will learn

  • The difference between block-level and inline elements, and what div and span are for.
  • Why layout belongs to div and CSS, not tables.
  • The semantic elements: header, nav, main, section, article, aside and footer.

Lecture content

Block and inline elements

Block elements Inline elements
Start on a new line Stay on the same line
Take the full width available Take only the space they need
Can contain block or inline elements Can only contain inline elements
Examples: div, p, h1, ul, table Examples: span, a, img, strong, em

div and span are generic containers. Use div for sections of block content and span for a small piece of text inside other content. Neither says anything about the meaning of its content.

Layout: tables or div?

Early web pages used tables to divide the page into header, content and footer. Today div is the preferred way to build page sections, because it is more flexible, easier to style with CSS and works better on different screen sizes. Reserve tables for real tabular data. You can also nest divs, for example a container holding a left and a right section.

Semantic elements

Semantic elements clearly describe their content, while div and span tell the browser nothing. Using them improves accessibility, maintainability and machine-readable structure.

header

Intro or branding.

nav

Navigation links.

main

The dominant content of the page.

section

A thematic group of content.

article

A self-contained item.

aside

Related side content.

footer

Ending information.

Memory trick

Think of a newspaper: header, menu, main story, side notes, footer.

Forms

A form turns a page into an interaction. The form element holds every control. Two attributes decide where the data goes:

action

The URL that receives the submission. If you leave it out, the current page is used.

method

GET sends data in the URL and suits small data. POST sends it in the request body and suits larger or private data.

When the user submits, the browser sends the data using each field's name and value, so every field needs a name. A label connects text to a control: clicking the label focuses the field.

Form controls

  • text name
  • email email address
  • password hidden text
  • number marks, quantity
  • date date of birth
  • checkbox several choices
  • radio one choice
  • file a document

Not everything is a text box: select makes a dropdown, textarea takes multi-line input, and button submits or resets. Use fieldset with legend to group related controls. Radio buttons with the same name form one group. placeholder shows a hint that disappears when the user types, and value sets a default.

HTML5 validation

required

The field cannot be empty.

pattern

The value must match a format, written as a regular expression.

min and max

Set the allowed range of a number, such as marks from 0 to 100.

Golden rule

The client is for convenience, and the server is the authority. Browser checks give fast feedback, but the server must still re-validate everything.

Accessibility

Connect each label to its control, group related controls with fieldset and legend, write meaningful alt text, and give clear instructions and error messages. Accessibility is part of professional web development, not an extra feature.

Coding-style conventions

  • Include both a start tag and an end tag for every container element, even where it is legal to omit one.
  • Use lowercase for tag names and attribute names.
  • Quote attribute values, with no spaces around the equals sign.
  • Use lowercase for attribute values unless there is a reason not to, such as a person's name.

Worked example: a student registration form

<form action="/register" method="post">
  <label for="reg">Registration no.</label>
  <input id="reg" name="reg"
         pattern="FA[0-9]{2}-BSE-[0-9]{3}" required>

  <label for="marks">Marks</label>
  <input type="number" id="marks" name="marks"
         min="0" max="100">

  <button type="submit">Register</button>
</form>

The pattern accepts FA24-BSE-019 but rejects FA24-BSE-19, because it needs exactly three digits at the end.

Quick check

Answer in your head first, then open the answer.

1. Name one difference between block and inline elements.

Block elements start on a new line and take the full width. Inline elements stay on the same line and take only the space they need.

2. Why use semantic elements instead of only div?

They describe their content, which helps accessibility, maintainability and machine-readable structure.

3. What decides where form data is sent, and how?

The action attribute gives the destination and the method attribute gives the HTTP method, GET or POST.

4. Is browser validation enough?

No. It gives fast feedback, but the server must validate again.

Tips and common mistakes

Common mistake

Using tables to lay out the page. Tables are only for data, and layout belongs to div and CSS.

Common mistake

Forgetting the name attribute on an input. Without it, the field's data is not sent on submission.

Pro tip

Always write label for="id" to match the input's id. It helps screen readers, and users can click the label to focus the field.
