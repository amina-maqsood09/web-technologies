Lecture content

Internet vs. Web

The Internet

A global network of billions of connected computers. It carries data between devices and networks.

The World Wide Web

A system of linked documents (web pages) and applications that runs on top of the Internet.

Think of the Internet as the roads and the Web as the services and content travelling on them.

Web platforms

A web platform is a digital environment that lets people use, build and deploy web-based applications and services. Examples include social media (Facebook, Instagram), e-commerce (Shopify, WooCommerce), content management systems (WordPress, Drupal) and cloud platforms (AWS, Google Cloud, Azure).

Infrastructure

Servers, databases and network resources.

Development tools

HTML, CSS, JavaScript, libraries and frameworks.

Content management

Tools to organize and deliver content.

User interface

Pages, forms and menus users touch.

APIs

Let different software systems talk to each other.

Security

Authentication, encryption and access control.

Memory trick

The first letters spell a sentence: Intelligent Developers Create User Applications Securely.

Creating a website

A website is a group of related pages, usually stored on one web server. A web server is a computer that lets users reach those pages. To make a website you need four things:

A text editor

To write the code. A plain editor stores exactly what you type. Authoring tools add suggestions (IntelliSense) and WYSIWYG, which shows the result while you edit. An IDE does this and also supports other kinds of software.

An upload tool

Publishing means uploading your page to a web server so other people can reach it. Some IDEs upload for you. Others need a separate tool such as WinSCP.

A hosting service

Uploaded files need a web server with hosting in place before they can be served as web pages.

A browser

Software that retrieves and shows web pages: Chrome, Edge, Firefox, Safari, Opera.

A file such as index.html on your own computer is only local. Other people can reach it only after it is uploaded to a server that serves it.

Client and server: request and response

When you open a website, the browser (client) sends an HTTP request. The web server processes it and sends back an HTTP response. The browser then renders the page.

URL and URI

A URL is the address of a resource. A URI is the broader idea of identifying a resource. Every URL is a URI, but not every URI is a URL.

DNS

You type google.com, but computers communicate with IP addresses. The Domain Name System (DNS) turns a name into an IP address, like a phone contacts list.

HTTP and HTTPS

HTTP is the protocol clients and servers use to communicate. HTTPS is HTTP over a TLS-protected connection, which adds encryption and server authentication.

Method What it does Everyday example
GET Retrieves data from the server Opening a web page
POST Sends data to be processed Submitting a form
PUT / PATCH Updates existing data Editing a saved record
DELETE Removes data Deleting a record
Status code Meaning Example
1xx Informational
2xx Success 200 OK
3xx Redirection
4xx Client error 404 Not Found
5xx Server error 500 Internal Server Error

HTTP messages also carry headers, extra information about the request or response. For example, Content-Type says what kind of data is being sent, and Authorization carries credentials for protected resources.

Web standards

Standards keep browsers and tools consistent so a page works the same way everywhere.

W3C

World Wide Web Consortium

WHATWG

Web Hypertext Application Technology Working Group

ECMA

Standardizes JavaScript (ECMAScript)

IETF

Internet Engineering Task Force

History of HTML

  1. 1989Tim Berners-Lee at CERN proposes hypertext links between research papers.
  2. 1989-1991He designs HTML, the ideas behind the Web including HTTP, and a prototype browser.
  3. 1993The first formal HTML proposal goes to the IETF.
  4. 1994Berners-Lee founds the W3C, which takes over HTML.
  5. 1997-2000HTML4 arrives in 1997. HTML 4.01 in 2000 is the last HTML4 revision.
  6. 2001XHTML 1.1 is too strict: a single error should stop the page from showing. Browsers and developers largely avoid it.
  7. 2004Some members leave the W3C and form WHATWG. They want backward compatibility and start Web Apps 1.0.
  8. 2009The W3C drops XHTML 2.0 and works with WHATWG. Web Apps 1.0 becomes the basis of HTML5.
  9. 2011-2017The HTML5 logo appears in 2011. HTML 5.1 becomes a W3C recommendation in 2017 and HTML 5.2 follows as a working draft.

XHTML added strict rules: quote attribute values, use / for void elements, and close container elements. Browser makers had added features beyond the standard to win market share, which made code harder to write and maintain. HTML5 brought useful features into one shared standard.

The W3C publishes stable, numbered versions. WHATWG keeps a living standard that updates continuously. They are separate organizations with closely aligned standards.

Types of web applications

Static

Prebuilt files served as they are. Example: portfolio or brochure site.

Dynamic

Content generated from data. Example: online store or portal.

MPA

Multi-Page Application. Moving between sections loads another page. Example: traditional university portal.

SPA

Single-Page Application. One main page whose views change dynamically. Example: Gmail-like apps.

PWA

Progressive Web Application. A web app with app-like abilities, such as being installable.

Picture a university website growing: a fixed brochure (static), then a portal showing your courses and marks (dynamic), then separate pages for courses and marks (MPA), then one page that changes its view (SPA), and finally something you can install like an app (PWA).

Worked example: reading a URL

An address is a map. Each part tells the browser something different.

https://www.example.com:443/courses/web?id=101#http
  • scheme https://
  • subdomain www
  • domain example.com
  • port :443
  • path /courses/web
  • query ?id=101
  • fragment #http

Now follow what happens when you type this address:

1. Browser asks DNS for the IP address of example.com
2. Browser sends an HTTP request (GET /courses/web?id=101)
3. Web server processes the request
4. Server sends back an HTTP response (for example, 200 OK)
5. Browser renders the page

Quick check

Answer in your head first, then open the answer.

1. What is the difference between the Internet and the Web?

The Internet is the global network infrastructure. The Web is a system of linked pages and applications that runs on top of it.

2. What is the relationship between a URL and a URI?

Every URL is a URI, but not every URI is a URL.

3. What does HTTPS add to HTTP?

A TLS-protected connection, which provides encryption and server authentication.

4. A server answers with status code 500. Who has the problem?

The server. 5xx codes are server errors, for example 500 Internal Server Error.

Tips and common mistakes

Common mistake

Treating the Internet and the Web as the same thing. The Web is only one service that uses the Internet.

Common mistake

Thinking a page is online because the file exists on your computer. It is only available to others after you publish it to a server.

Pro tip

Remember status codes by the first digit: 2 means success, 4 means the request was wrong, and 5 means the server failed.
